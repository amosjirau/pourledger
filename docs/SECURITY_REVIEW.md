# Sprint security review

Internal review and automated checks for the existing non-upgradeable registry. No independent audit or certification has been completed. The sprint did not change Solidity application code.

| Area | Verified behavior | Residual risk and release condition |
| --- | --- | --- |
| Suppliers | The named supplier can register for an existing project. Registration has zero accepted or assigned quantity, and the UI labels it a supplier declaration. | A supplier can add noise or reserve a predictable lot digest. Use unguessable lot identifiers and separate supplier and inspector accounts. No extra supervisor approval state was introduced. |
| Role scope | Role mutations require the project supervisor. Inspector, engineer and lab checks occur at execution for the lot's project. | A supervisor can grant a supplier an inspector role. Lost supervisor keys have no recovery path. Review a multisig supervisor, independent role holders, and recovery signers before any public project. |
| Compromised role signer | Revocation blocks future use while revoked. Typed messages bind signer, action, entity IDs, amounts/digests, domain, deadline and nonce. | A role can record false claims while authorized. Such receipts stay permanent. Regrant can enable a still-valid signature, and concurrent signatures contend for one per-signer nonce. Reorgs may restore consumed nonces. |
| Allocation | The lot has a single immutable unit. The frontend checks project and available quantity before prompting. The contract enforces `assigned <= accepted <= declared`, including partial and rejected cases. | Validation does not establish actual material quantity or delivery. Custom unit hashes require out-of-band interpretation. |
| Receipt provenance | App config pins chain, registry and deployment range. Reads compare code/domain, successful receipt, canonical block, event signature and fields, then cross-check state at a pinned block. | The server trusts an operator-selected RPC for its responses and log completeness. Wallet transaction progress trusts the connected provider. No QIE finality claims were measured. History limits can make views unavailable. |
| Evidence | QR paths pin chain, registry, type and ID. File checks hash exact bytes locally and the browser test checks that public verification sends no upload. | Digests and addresses are public and permanent. Predictable or sparse evidence can be guessed. No private storage, public document URLs, civil identity, document validity, or scientific certification are provided. |
| Deployment | The preflight verifies compiled init/runtime hashes and rejects the wrong chain before gas estimation. It outputs an unsigned envelope. | Read-only QIE network checks were blocked. Testnet and independent source and release review remain deployment gates. |

No high or critical defect was identified in the code paths reviewed and tested locally. Production launch remains gated on an owner review, legitimate wallet and QIE rehearsals, verified artifact and explorer checks, and hosting smoke tests. Review [threat model](threat-model.md), [contract specification](contract-spec.md), and [checks](TEST_EVIDENCE.md) before deployment.

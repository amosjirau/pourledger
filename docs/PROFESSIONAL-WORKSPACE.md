# Professional construction workspace

The professional preview uses private PostgreSQL records in the `construction` schema. The index reader uses a separate database credential. The existing registry, production edition and canonical passport URLs are shared only where the preview verifies an existing on-chain reference. Publishing workspace labels or documents on passports requires a separate disclosure policy.

## Bootstrap and access

1. Provision a dedicated PostgreSQL database with a schema owner and an application role. Restrict both to private access. Scope the construction database variable and separate tunnel key to the professional preview. See [the indexer runbook](VERIFIED-INDEXER.md) for SSH and TLS pinning.
2. Set `POURLEDGER_CONSTRUCTION_ADMIN_DATABASE_URL` for the migration process only. Run `node professional/migrate.mjs` from `apps/web`. It locks and checksums migrations and rolls back an unsuccessful migration.
3. Grant the application role schema usage and the table privileges needed by the active migrations. The app needs read and insert on accounts, project membership, document revisions, audit events and deliveries, and update on the project, invitation, document, inspection, specification and element records. Session and rate limit tables require their own limited deletion privileges. Keep migrations and schema ownership out of the web process.
4. As the host operator, run `node professional/create-organization.mjs "<organization>" "<administrator email>"` with the application URL configured privately. Treat the returned 48-hour invitation as a secret. At `/construction`, the administrator accepts it using the invited address and a private password.
5. The administrator invites personnel, creates a project and grants project access. The account roles control this workspace. The registry still requires the appropriate wallet and on-chain authority for writes. Use the live registry's established approval interface when an authorized signer is ready.

## Workflows

- **Projects and personnel.** Record project and contract metadata, location, approvals context and work locations. Project managers can create records and assigned personnel can see the relevant project. Project revisions and access grants appear in the audit history.
- **Private documents.** Use **Project documents** to file PDFs, PNGs or JPEGs up to 3 MiB, create revisions, inspect digests and download an exact authorized revision. Each download rechecks bytes against SHA-256 and Keccak-256 and records access. Archived files retain their history. Keep the original evidence packages according to approved site retention policies.
- **Delivery and MIR.** Use **Material deliveries and inspections** to record a delivery, find it by reference or supplier, file inspection observations and submit a specific evidence revision. An assigned inspector or consultant other than the author reviews it. The decision balances accepted, rejected and quarantined quantities without rounding. Export a CSV from the register. An internal reviewed decision and an immutable registry attestation have separate provenance.
- **Specifications and elements.** File standards or contractual requirements with the exact edition, amendments, source and project applicability. A separate authorized engineer or consultant approves a project revision. Official Nigerian Industrial Standards are available through the [SON Digital Standards Platform](https://nnsdp.son.gov.ng/). Consult the applicable publisher and contract for any source edition before approval. Register human-readable elements, drawings and locations. Supplying an existing Mainnet element ID verifies the project and element type through the canonical passport before linking it.
- **Quality registers.** File an ITP against an approved specification revision. Record WIRs against specific elements, and maintain nonconformance, concrete pour, laboratory and reinforcement records. The due queue shows submitted records and upcoming or overdue dates. A separate reviewer records the assessment or verifies an NCR closure. ITP activity choices require the project to supply its own criteria. A laboratory record can calculate specimen strength from the observed failure load and loaded area, with no automatic conformity decision.
- **Warehouse stock.** Use a reviewed workspace MIR to unlock allocation to an element. The ledger distinguishes allocated, installed, returned, wasted and available quantities. A site or structural engineer files installation evidence. Trace delivery–element relationships in either direction.
- **Calculations.** Use the workspace tool for theoretical rebar quantity and mass, rectangular volumes, specimen strength, utilization and SI conversions. Figures use entered dimensions and stated formulas. Use the exact decimal stock ledger for actual reconciliation.

## Backup, recovery and limits

Keep role and tunnel credentials in root-only settings, separate from custom-format database backups. Restore a backup to a new private database, validate migration checksums and authorize the correct database role before switching the preview. Rerun the database regression and smoke checks after recovery. Rotate the preview SSH key and Vercel secret separately from production credentials.

Approval uses role separation and durable audit. Deployment-level network controls and application authorization are both required. The workspace does not certify compliance, engineering safety or accreditation. Private document storage has a 100 MiB organization quota. Permanent retention-policy deletion, account recovery, PDF handover dossiers, broadcast signing integrations and external notifications are future work.

From `apps/web`, run `node --test professional/integration.test.mjs` using `POURLEDGER_CONSTRUCTION_TEST_DATABASE_URL` for a disposable loopback database with migrations and app grants. The scenario uses synthetic records and sends no blockchain transactions.

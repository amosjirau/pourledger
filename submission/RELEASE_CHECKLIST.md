# Release and submission checklist

**Local MVP verified. Final hackathon submission pending.**

| Gate | Current state | Required proof |
| --- | --- | --- |
| Original source | Local commits only | Owner-approved GitHub repository URL and matching published SHA |
| QIE Testnet | NOT DEPLOYED | Separately approved Testnet role workflow, address and real receipt proof |
| QIE Mainnet | NOT DEPLOYED | Approved chain 1990 deployment, verified contract address, creation transaction and explorer proof |
| Public HTTPS site | NOT DEPLOYED | Owner-approved host, working app URL and second-device passport QR smoke |
| Demo media | Local capture complete | Public demo video URL that reflects the actual deployed environment |
| Team and registration | Owner action | Team names and registration details, with consent |
| Eligibility and terms | Owner action | Current rules and acknowledgements from the submitting team |
| Originality and human review | Owner action | Explain role and nonce checks, allocation math, receipt verification and privacy boundaries. Review AI-assisted contributions and identify third-party code. |
| Submission portal | Owner action | Final review and submission after public links, required proof, and team information are complete |

Before listing a public site, open it in a clean browser on desktop and mobile, compare the displayed network and contract with the verified explorer, verify the sample passport, and review usage claims. Use [release procedure](../docs/DEPLOYMENT.md), [submission copy](SUBMISSION.md), and the [demo script](DEMO_SCRIPT.md).
